# 松山湖产业招商网站

网站：https://ning73988-jpg.github.io/songshanhu-enterprise-spaces/

## 当前版本

- 电脑端使用宽屏导航、搜索和房源网格；手机端使用小程序风格与底部导航。同一套真实房源数据，不包含模拟手机时间、电量或设备边框。
- 房源读取 Supabase 已发布公开视图；园区、地址、招商联系人和电话由发布方决定填写。内部编号、底价和跟进备注保持后台权限控制。
- 支持关键词、园区、业态、租金、面积等筛选，详情相册展示全部照片，并展示已上传视频。支持分享链接与海报生成。
- 管理后台 `/admin/` 使用已授权 Supabase 账号，支持照片/视频上传、草稿、发布和咨询列表。
- 智能找房采用预算、面积、装修等条件解析；尚未连接外部大模型。访客资料、企业资料与需求保存在当前浏览器，未提供跨设备访客登录。
- 已准备高德 JS API 2.0 接入代码：拖动缩放、按真实经纬度展示房源价格标记、点击打开详情；不使用静态图片作为地图。尚待云端安全密钥、代理函数部署及网站重新发布，线上地图未开通。配置参见 `supabase/functions/amap-proxy/README.md`。

## 发布与数据

线上工作流从仓库根目录 `site-source-v3.tar.gz` 解包完整源码，然后构建 GitHub Pages。不要只修改外层页面而忽略源码包。当前源码和线上仓库历史不同，不要强制推送覆盖线上历史。

`NEXT_PUBLIC_SUPABASE_URL` 和 `NEXT_PUBLIC_SUPABASE_ANON_KEY` 由 GitHub Actions Secrets 提供，不在源码中保存管理凭据。

已有 Supabase 项目已经执行 `supabase/port_workbuddy.sql`，支持公开园区、地址、联系电话及至少一张房源照片的发布规则。新项目参见 `supabase/README.md`。

## 开发

Node.js 22，执行 `npm ci`、`npm run dev`。配置上述公开环境变量后构建；不要使用 service_role 凭据作为前端配置。

## 管理员登录与上传

- 使用在 Supabase Authentication 中创建并授权的邮箱和密码登录；不支持 `admin` 用户名或 WorkBuddy 密码。浏览器会保留本站登录会话，公用设备用完请退出。
- 后台显示当前账号的超级管理员或园区管理员身份，并核对 `active` 状态。
- 新增房源后上传照片/视频，点击“保存草稿”或“发布房源”。发布需标题、园区名称和至少一张真实照片；已有公开房源可下架为草稿。
- 批量上传按文件显示进度，失败文件会明确列出，已成功的文件保留。图片上传后仍需保存房源。HEIC/HEIF 请先导出为 JPG。

## 第一轮交互改进

- 保留原有蓝白视觉及电脑/手机布局。原生 CSS 与 Web Animations 提供按压、水波、卡片和筛选反馈，支持系统减少动态效果设置。
- 房源图片加载占位及全屏相册：前后切图、键盘操作、按钮/双击/双指缩放、放大后拖动。
- 筛选面板使用独立暂存选择并预览结果数量；取消不提交筛选。列表变化时保留滚动与搜索焦点。
- 安全后台使用 XHR 提供实际上传进度，100% 仅在服务器成功回应后显示。照片可拖动、箭头排序及设为封面；保存后生效。
- 保存、发布、预约只在服务器成功回应后显示成功反馈。字段校验定位到具体输入项；失败保留输入。

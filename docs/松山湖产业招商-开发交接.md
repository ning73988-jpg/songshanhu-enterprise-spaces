## 4. 已确认的产品决定及原因

| 决定 | 原因及维护要求 |
| --- | --- |
| 网页 → 微信小程序 → App | 先跑通找房与招商业务，再投入平台适配。现有 DOM/CSS 不能一键变成原生小程序；可复用数据库、费用规则、类型和服务逻辑。 |

| 新增房源只提供“写字楼 / 厂房” | 用户明确去掉“研发办公”；已有研发办公/仓储记录不能擅自改写或丢失。 |

| 牛角记录为“行车支撑” | 指天车两侧支撑，不等于已经装有行车设备。 |

| 内部编号、底价、跟进记录不公开 | 后端出口必须隔离，不能只用 CSS 隐藏。 |
| 对外园区、楼栋、楼层、房号、地址、坐标可控 | 以 `field_visibility` 为依据；旧合并楼栋/房号保留，人工拆分后再用新字段。 |

| 费用只折叠金额明细 | 联系方式必须直接可见，不随费用收起。最新顺序按用户文字要求放在介绍下、参数上。 |
| 相册只有一组箭头，主图/右侧预览联动 | 用户明确不需要每个预览再加箭头；手指和鼠标均应水平滑动。 |
| 首页只保留筛选及 3 个排序 | 用户否决新增的 3 个快捷筛选；完整面板仍保留园区、面积等条件。 |

- Edge Functions：`ai-search`、`admin-accounts`、`amap-proxy`。不要仅因源码有文件就认定云函数已更新，部署状态需要只读核对。
- 服务端 Secret 例子：`DEEPSEEK_API_KEY`；高德安全配置和管理凭据也只留服务端。不复制真实值到文档/仓库。
- 目前函数来源限制主要绑定 `https://ning73988-jpg.github.io`；AI 源码另有本地预览来源。新域名及新本地端口不一定天然可用，不能用关闭来源检查解决。

## 7. 当前发布方式：必须读

**远端根目录采用“基础源码压缩包 + 更新包”构建，和本机展开的源码不是同一份 Git 历史。**

```text

  → 解码并覆盖 site-update.tar.gz.b64
  → 根据 GitHub Secrets 生成公开 config.js

  → npm run build（静态导出）
```

- 本机旧 HEAD 为 `057d07d`（10 月 16 日）；后面的很多改动在当前工作区和发布更新包里，未逐项形成对应本地提交。

- 当前真实远端工作流已另存 `private-notes/pages.yml.remote`；不要用本机旧 `.github/workflows/pages.yml` 替换。
- `scripts/package-site-update.py` 遍历工作区已跟踪及未忽略的新文件，与 v3 基础包对比；输出在源码目录的父目录。

- 外层 README 和直接可浏览的 docs 需要另外同步；只有把文档打进压缩包，并不能让 GitHub 文件列表直接显示它。
- 本次迁移保持既有发布方式。未来应单独规划转为正常展开源码仓库，不能趁交接随手删除旧包或改工作流。

## 9. 在独立源码目录恢复和运行

1. 使用完整备份或已经恢复的独立 `source/`，不要只 checkout 旧 HEAD。
2. 使用 Node 22 作为与 CI 一致的基线，运行 `npm ci`。可使用可信 npm 官方仓库和本机缓存；离线缓存缺包时不能误认为安装成功。
3. 在本机 `.env.local` 填入经所有者确认的公开前端配置（模板见下）。此文件不进入 GitHub。
4. `npm run dev` 启动开发服务器，实际前台在 `/experience/`，管理页在 `/admin/`。从临时端口调用 AI/账号/地图代理时需核对来源允许列表。
5. 构建 GitHub Pages 版本：静态导出开关 `GITHUB_PAGES=true`、base path 为 `/songshanhu-enterprise-spaces`；执行 `npm run build`，生成 `out/`。
